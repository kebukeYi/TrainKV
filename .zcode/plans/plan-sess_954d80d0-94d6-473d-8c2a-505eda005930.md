## 孤儿 FIN bug 三层修复方案

### 背景（根因）
一个事务请求的所有条目（含 finTxn 结束标记）在 `writeToLSM` 中**逐条**经 `LSM.Put` 写入，而 memtable 轮转检查也是逐条做的（lsm/lsm.go:51）。当某条数据的轮转预判通过、紧跟其后的 finTxn 预判失败时，`Rotate()` 把 fin 写进新 WAL，数据留在旧 WAL；旧 WAL flush 成 SST 后被删，重开时新 WAL 头部出现"孤儿 FIN"，`recovery2SkipList` 在 `lastCommitTs==0` 时遇 `BitFinTxn` 必然返回 ErrBadTxn → `Open` 直接 panic（memTable.go:231-235，已由复现确认）。另一个独立来源：**空事务 Commit 也会无条件生成纯 fin-only 请求**（txn.go:422），同样制造孤儿 FIN。

### 改动（三层）

**① 写路径预防：请求级轮转（lsm/lsm.go + db.go）**
- lsm 包新增 `LSM.RotateIfNeed(entries []*model.Entry)`：len==0 直接返回；累加 `skl.EstimateEntryMemSize`（导出且为严格上界）得整请求占用量 `need`；若 `need > MemTableSize`（单表放不下的病态配置）则直接返回、退回逐条轮转旧行为并注释说明；否则 `MemBytes()+need > MemTableSize` 时先 `Rotate()` 一次。
- db.go `writeToLSM`：进入逐条循环前先调 `db.Lsm.RotateIfNeed(req.Entries)`；循环内 meta 变更/写 WAL 的交错与错误停止语义保持不变（与现行为逐字节一致）。效果：同一请求（同一事务 data+fin）整体落在同一个 memtable/WAL，轮转只发生在请求边界；GC/discard-stats 等普通批次也顺带获得"整批同表"的崩溃原子性。

**② 空事务不再产生 fin-only 写请求（txn.go）**
- `commitAndSendToDB`：pendingKeys 为空时跳过 fin 构造与 `SendToWriteCh`，直接返回闭包 `{ manager.doneCommit(commitTs); return commitTs, nil }`。newCommitTs 已做的 commitTs 消费、冲突检测、commitedTxns 记录全部保留；writeChLock 顺序不变。安全性：LimitMark 的 done-index 按最小堆单调推进，后分配的 commitTs 提前 Done 不会跳过未完成的更小 index（limiterMark.go processOn）。

**③ 重放容错：跳过孤儿 FIN（lsm/memTable.go）**
- `recovery2SkipList` 的 `BitFinTxn` 分支开头加 `if lastCommitTs == 0 { continue }`：孤儿 FIN（旧版拆裂或空事务残留）视为无效记录跳过，不推进 validEndOffset（与 BitTxn 分支一致），后续正常 fin 照常推进；仍有未完成事务时的 fin 值不匹配依旧返回 ErrBadTxn（不放松对真实损坏的检测）。存量旧格式库（含 benchmark 遗留数据）重开不再 panic。

### 测试
1. **lsm 包恢复单元测试**（新文件如 memTable_recovery_test.go）：用 OpenWalFile + wal.Write 构造两种 WAL：a) 首条即孤儿 FIN(ts2) 后跟完整事务 data(ts3)+fin(ts3)；b) [data(ts1) fin(ts1) 孤儿FIN(ts2)]。断言 `recovery2SkipList` 返回 nil、只恢复含数据的 ts1/ts3。旧代码下此测试必红（ErrBadTxn）。
2. **根包 e2e 回归**（db_test.go，沿用 txn_test.go 的 MkdirTemp+defer removeAll 惯例）：
   - 空事务用例：`NewTransaction(true)` 后不 Set 直接 Commit → Close → 重 Open 必须成功（旧代码确定性 panic）。
   - 多轮转完整性用例：提交覆盖多次 memtable 轮转的数据 → Close → 重 Open → 校验全部 key 可读、计数一致。
3. **benchmk/ycsb_repro_test.go**：删除关库前 `db.Lsm.Rotate()` 的 workaround（不再需要），保留 ErrConflict 重试；重跑确认 load→reopen→workloadA 全绿（兼作长链回归）。

### 验证
- `go test ./...` 全量；对 root、lsm、benchmk 相关用例再跑一遍确认无回归
- benchmk 复现：无 workaround 情况下 load 100 万条 → Close → reopen → workloadA 全绿
